# Exam Prep — 學習講義與考試複習包產生器

把使用者的學習資料變成「印出來就能讀、寫、對答案」的 PDF。可產出的文件（題目和解答分開，寫題時不會偷看到答案）：

| 文件 | kind | 用途與內容 |
|---|---|---|
| `<科目>_學習講義.pdf` | `handout` | **用來學懂**：把所有教材整合成一份完整、詳盡、可自學的講義——動機、定義、直觀解釋、定理與證明、完整例題、章末自我檢測 |
| `<科目>_重點整理.pdf` | `notes` | **用來複習**：依章節的重點、定義、定理、易錯、常考標記、考古題分析 |
| `<科目>_練習題.pdf` | `practice` | 題目卡，含題型、難度、作答空白 |
| `<科目>_解答.pdf` | `answers` | 逐題解答與解題思路，計算題標「✓ 已驗算」 |
| `<科目>_公式小抄.pdf` | `cheatsheet` | 雙欄高密度，公式與關鍵結論 |

學習講義和重點整理的差別：講義是**第一次學、或沒聽懂時從頭讀**的，要把每個觀念講清楚，篇幅長是正常的；重點整理是**已經學過、考前快速回顧**的，要精簡。

語言：學習講義、重點整理與公式小抄以繁體中文為主，**術語第一次出現時中英並列**，例如「特徵值 (eigenvalue)」，讓中英文考卷都看得懂。練習題與解答的語言由使用者選（見第 2 步），規則見 `references/question-design.md` 的「語言」一節。

## 工作流程

### 1. 先讀完所有資料，再問問題

先把資料讀過一遍再問使用者，因為「考試範圍」的選項應該是資料裡真的有的章節，而不是空泛的猜測。讀法依資料類型見 `references/reading-inputs.md`（投影片、PPT、掃描/手寫照片、考古題、**Google Drive 連結或資料夾**各有不同處理）。

資料來源可以是對話中上傳的檔案，也可以是 Google Drive 的檔案或資料夾連結。使用者提到 Drive、貼了 `drive.google.com`／`docs.google.com` 連結，或說「在我雲端的某資料夾」時，用 Google Drive 連接器讀取；沒有連接器就建議連接，或請他直接上傳。

讀完後在心裡建立一份**內容地圖**：章節 → 概念 → 每個概念的定義/定理/公式/例子，以及每項內容出現在哪份資料。有考古題的話，記下每題考哪個概念、什麼題型、多難——這是判斷「常考」最可靠的依據。

### 2. 執行時詢問（分兩輪，每輪最多 4 題）

用 AskUserQuestion 問使用者。**使用者訊息裡已經講清楚的項目就跳過**，不要重問；全部都講了就直接開始。使用者說「整理教材」「做成講義」「我沒聽懂，幫我從頭整理」這類話時，等於已經選了學習講義，第 2 題只需確認還要不要其他文件。

**第一輪**
1. **範圍** — 選項用資料中的實際章節名（可複選），外加「全部」
2. **要產出哪些文件**（可複選）— 學習講義／重點整理／練習題＋解答／公式小抄
3. **主題風格** — 現代筆記風 `modern`（推薦）／教科書風 `textbook`／精簡小抄風 `cheatsheet`（說明欄註明：小抄風只套用在公式小抄，學習講義選它時改用教科書風）
4. **考古題用法**（只在有考古題時問，可複選）— 在講義/重點中標出常考／練習題模仿考古題題型與難度／逐題詳解考古題本身

**第二輪**（只有要產出練習題時才需要第 5、7 題）
5. **題型與題數** — 例如「混合 15 題（推薦）」、「選擇/是非為主 20 題」、「計算＋證明為主 10 題」；理工科才提供證明題、計算題選項
6. **難度與考試日期** — 難度：基礎／混合（推薦）／挑戰；日期請使用者用 Other 填寫或選「不確定」
7. **練習題語言** — 選項：
   - **跟考古題一樣**（有考古題時放第一個並標推薦；說明欄寫出考古題實際用的語言，例如「英文題幹、部分中文」）
   - **中文**（術語中英並列）
   - **英文**（和英文考卷的用語一致）
   - **中英對照**（中文題幹下方附英文翻譯，適合想同時熟悉兩種說法）

   沒有考古題時，第一個選項改成和講義相同的語言並標推薦。

**沒人可問時的預設值**（排程執行或使用者不回應）：範圍＝全部資料；文件＝重點整理＋練習題＋解答（使用者的話明顯是要學習/整理教材時，改為學習講義＋練習題＋解答）；主題＝`modern`；混合題型 12–15 題；難度混合（基礎 40%／中等 40%／挑戰 20%）；考古題兩種用法都做；練習題語言＝跟考古題一樣（沒有考古題就用中文）。在回覆開頭用一句話說明採用了哪些預設。

**考試日期會改變寫法**：
- ≤ 3 天：重點整理精簡、優先常考，主動建議加做公式小抄。若使用者選了學習講義，照做（不刪減內容），但在回覆中提一句「時間緊的話可以先讀重點整理」
- 4–13 天：標準深度
- ≥ 14 天：重點整理可加入推導過程與觀念連結；學習講義的「延伸」內容可以多寫一些

所有 Markdown 都按照 `references/markdown-format.md` 的語法撰寫，它支援數學公式、彩色重點框（定義/定理/公式/例題/易錯/常考/技巧/補充/摘要）、徽章、題目卡、分頁。**寫之前先讀它。**

### 3a. 寫學習講義（選了學習講義時）

目標：一個**沒去上課**的同學，只讀這份講義就能把這個範圍學會。所以不能只列重點——每個觀念都要交代「是什麼、為什麼、怎麼用、哪裡會錯」。

**整合所有資料，不要丟內容**
- **投影片／上課講義**決定章節順序、符號和用語（考試用的就是老師的版本）
- **課本**補足投影片省略的推導、條件和例子
- **手寫筆記**代表老師上課特別強調或口頭補充的內容，用 `:::hot 老師上課強調` 標出
- **考古題**用來標 `{{常考}}`，也可以改編成講義中的例題
- **作業**的題目可以作為例題或自我檢測題
- 內容地圖裡的**每一個**定義、定理、公式、例子都要出現在講義中；寫完後對照內容地圖逐項檢查有沒有遺漏
- 不同資料的符號或說法不一致時，以投影片為準，並用一句話註明另一種寫法（例如「課本把特徵空間寫成 $E_\lambda$」）
- 資料以外補充的內容（背景、補充推導、延伸應用）照樣放進 `:::extra` 或加 `{{補充}}`

**每一章的結構**
1. `## 章名`，接著一個不帶標題的 `:::summary`：2–3 句說明這章要解決什麼問題、和前一章的關係，再接「**學完本章你應該能夠：**」加 3–5 條可檢驗的學習目標（「能判斷一個矩陣是否可對角化」，而不是「了解對角化」）
2. 依概念分 `###` 小節，每個概念依序寫：
   - **動機**：用一兩段文字說明為什麼需要這個概念（從一個具體問題或前一個概念的不足引入）
   - **定義**：`:::def`，用教材的正式定義
   - **直觀理解**：用文字、幾何意義或類比解釋定義在說什麼，`:::tip 直觀理解`
   - **定理**：`:::thm`，標題寫上編號與名稱（例如 `:::thm 定理 5.2　對角化定理`，編號沿用教材的，教材沒有就按章節自編）。定理框內接著寫**證明**：短證明（≤ 10 行）寫完整；長證明寫證明概要並說明關鍵想法；教材沒有附證明而自己補的，在證明前加 `{{補充}}`
   - **完整例題**：`:::example`，每一步都寫出來並說明為什麼這樣做，不跳步。每個重要方法至少一題；有標準解題流程的（例如判斷可否對角化），先用 `:::tip` 列出步驟，再用例題走一遍
   - **常見錯誤**：`:::warn`，寫具體的錯誤做法和為什麼錯
   - **觀念連結**：一兩句話說明這個概念和前面哪些概念有關
3. `### 本章重點回顧`：條列本章最重要的結論（這是重點整理的濃縮版）
4. `### 隨堂自我檢測`：3–5 題 `:::q`，以觀念題與簡單計算為主，用來確認有沒有讀懂（不需要作答空白）

**講義最後**
- `<!-- pagebreak -->` 後接 `## 自我檢測解答`，用 `:::a` 逐題解答，同樣要驗算並標 `✓ 已驗算` 或 `無法程式驗算`
- 題號全份講義連續編號（1、2、3…，渲染器只接受整數題號），解答題號與題目一致
- 有考古題時，最後加 `## 考古題分析`（`:::past`），和重點整理的做法相同

**格式細節**
- Front matter：`kind: handout`、`toc: true`；**不要填 `course` 欄位**，把科目名稱放進 `subtitle`（例如 `subtitle: 線性代數 CE2005 · Ch5 特徵值與對角化`）
- 每個 `##` 章之前（第一章除外）加 `<!-- pagebreak -->`，讓每章從新頁開始
- 標題不要手動編號（教科書主題會自動編號）；定理編號寫在框的標題裡即可
- 用完整的段落解釋觀念，而不是全部寫成條列——講義是要讀懂的，條列適合回顧不適合教學
- 篇幅參考：一堂課（約 2–3 小時）的教材，講義大約 6–12 頁；寧可詳盡，但不要灌水重複

### 3b. 寫重點整理（選了重點整理時）

好的重點整理不是把講義濃縮，而是**幫使用者決定什麼值得記**：
- 每章以 `:::summary` 開頭（3–5 句，這章在解決什麼問題）
- 定義、定理、公式各自用對應的框，讓讀者一眼辨識類型
- 每個重要觀念配一個小例子——抽象定理配具體數字最好記
- `:::warn` 寫學生實際會犯的錯（例如矩陣乘法順序、條件機率方向搞反），而不是泛泛提醒
- 有考古題時，常考概念加 `{{常考}}`，並在最後一章用 `:::past` 做出題分布分析
- **來源規則**：內容以使用者資料為主。資料沒有、但對理解或解題必要的內容可以補充，**必須**放在 `:::extra` 框裡或加 `{{補充}}` 徽章——使用者需要知道哪些東西老師可能沒教、不一定會考
- 標題不要手動編號（教科書主題會自動編號，手動編號會重複）

同時產出學習講義和重點整理時，兩份內容一致（同樣的符號、同樣的例子編號方式），重點整理可以在開頭註明「詳細說明見學習講義」。

### 4. 出練習題與解答

詳細出題原則見 `references/question-design.md`（題型、難度校準、誘答選項、模仿考古題的方法、解答寫法）。重點：
- 題目要涵蓋所選範圍，分配大致依「概念重要性 × 常考程度」
- 題號在練習題與解答兩份文件中一致
- 計算題、證明題在練習題中加作答空白 `space=N`
- 解答要寫**思路**而不只是答案：先說用哪個觀念、為什麼，再算
- 同時有學習講義時，練習題不要和講義的例題、自我檢測題重複

### 5. 驗算（不可省略）

模型心算會出錯，而錯的解答會讓使用者白練、甚至學錯。所有有確定數值/符號答案的題目，都要用 Python 實際算一次：

```bash
pip install --break-system-packages -q sympy numpy scipy 2>/dev/null
```

比較答案的工具已寫在 `scripts/verify_helpers.py`（`check`、`is_eigvec`、`summary`），流程與範本見 `references/verification.md`。原則：
- 每題寫一小段程式重算，結果和解答不符時**修正解答**（或修題目），不要硬湊
- 通過驗算的解答標 `✓ 已驗算`；證明題、申論題、概念說明等無法程式驗算的題目標 `無法程式驗算`，並在解答中寫明關鍵檢查點
- 選擇題的正確選項也要驗：確認只有一個選項正確，誘答選項確實是錯的（化簡後相等的選項很容易不小心出現兩個正解）
- **講義與重點整理裡的數字也要驗**：例題的每個計算結果、考古題配分統計、「每年都考」這類說法，同樣寫進 `verify.py` 檢查——學習講義的例題錯了，使用者會照著錯的方法學

### 6. 渲染 PDF

```bash
node <skill-dir>/scripts/render.mjs handout.md 線性代數_學習講義.pdf --theme modern
```

- `--theme`：`modern` | `textbook` | `cheatsheet`（公式小抄一律用 `cheatsheet`；學習講義不用 `cheatsheet`，使用者選了它就改用 `textbook`；其他文件用使用者選的主題）
- 腳本會自動安裝缺少的 npm 套件（katex、marked、playwright）到 `~/.exam-prep-deps`；若環境已有全域安裝，先設 `NODE_PATH` 指向它
- 加 `--html out.html` 可保留中間 HTML 方便除錯

### 7. 檢查排版，再交付

渲染後**實際看一眼**：用 `pdftoppm -r 60 -png file.pdf preview` 轉成圖片，至少檢視第 1 頁、題目或公式最密集的一頁；學習講義另外抽看中間幾頁。常見問題：
- 公式顯示成紅色原始碼 → KaTeX 不支援的語法，改寫該公式
- 寬表格或長公式超出頁面 → 拆開或改用 `aligned` 換行
- 小抄超過預期頁數 → 刪減次要內容，小抄的價值在於精簡
- 學習講義只有幾頁、大多是條列 → 寫得太像重點整理，回到 3a 補上動機、直觀解釋與完整例題

確認無誤後把 PDF 交給使用者，用一兩句話說明涵蓋範圍、頁數或題數、有幾題無法程式驗算。不要在對話中重述文件內容。

## 檔案說明

- `scripts/render.mjs` — Markdown → 主題化 PDF 的渲染器
- `scripts/verify_helpers.py` — 驗算用的比較工具
- `assets/themes/*.css` — 三套主題與共用基礎樣式
- `references/markdown-format.md` — 撰寫語法（重點框、徽章、題目卡、分頁）**寫 Markdown 前必讀**
- `references/question-design.md` — 出題與解答撰寫指南
- `references/verification.md` — 驗算流程與 SymPy 範本
- `references/reading-inputs.md` — 各類輸入資料的讀取方式
