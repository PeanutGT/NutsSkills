# music-studio 進程與目標

這份檔案分兩半：上半部是**目標與規則**（很少改），下半部是**進度清單與變更紀錄**（每個 PR 更新）。

---

## 一、目標

### 終點

在使用者的 **RTX 3050 4GB** 上，達成 [yovoice](https://github.com/leemysw/yovoice) 音樂端的**能力對等**，再加上 MCP 接口與音訊轉 MIDI。
下方「進度清單」每一項都 ✅ 時即為終點。終點達成後才解禁語音 / TTS。

### 範圍原則

- **只做音樂**（含人聲歌、音效）。語音 / TTS 在終點之後。
- **能力對等，不求模型對等**：跑不進 4GB 的模型可用替代方案（例如人聲歌用 ACE-Step 歌詞模式代替 YuE2）。
  - ⚠️ 這是**暫時決定**：換顯卡後重新評估，引擎接口要保留接回原模型的空間。
- **形態（2026-11-09 改）**：重寫成獨立桌面 app（Tauri 2 + React），另開新 repo；本 skill 凍結在 v3.7，只修 bug。詳見下方「App 路線」。
- 多語系：app v1 只做繁中介面，但字串集中管理，之後再加英文。

### 驗收標準（每一項都適用）

一項能力要打 ✅，需同時滿足：

1. 在 RTX 3050 4GB 上**連跑 3 次**：不卡死、取消有效、不掉到 CPU 解碼。
2. **Peanut 試聽過關**（主觀可用）。不設生成時間上限。

### 狀態符號

| 符號 | 意思 | 誰勾 |
|---|---|---|
| ⬜ | 未開始 | |
| 🚧 | 開發中（有分支 / PR） | 開 PR 時 |
| 🛠 | 已合併，未在 GPU 驗收 | PR 合併時 |
| ✅ | 已驗收（附日期與一句試聽心得） | Peanut 實測後 |

雲端開發環境沒有 GPU，只能跑 mock 測試，所以「合併」不等於「完成」。

### 推進規則

- **M0 是硬門檻**：M0 未 ✅ 前，只做 M0 相關修正。
- M0 通過後，**最多 1 個里程碑**可以停在 🛠 未驗收狀態；要開下一個，得先把它驗收掉。
- 一步一個分支一個 PR，PR 合併時更新下方清單與變更紀錄。

## 二、里程碑

| 里程碑 | 內容 | 對應能力 |
|---|---|---|
| **M0** 穩定 v3 | 常駐引擎在 4GB 上實測；通過後移除 WIP 標記 | 文字生音樂（純音樂 / BGM / 循環） |
| **M1** 自動品檢 | 響度預設、自動品質檢查（補足主觀試聽） | 品質基礎 |
| **M2** 第二引擎 | audio.cpp + Stable Audio 3 Small（Q8 約 1.68 GB）先做可行性試做 | 音效、remix |
| **M3** MCP | stdio MCP 伺服器，讓 Claude 直接操作 | 工具接口 |
| **M4** 人聲 | 歌詞輸入、人聲歌（ACE-Step 歌詞模式） | 人聲歌 |
| **M5** 轉譜 | 生成結果 → MIDI / 簡譜（例如 basic-pitch，CPU 可跑） | 音訊轉 MIDI |

**重繪 / 翻唱**另列一項：ACE-Step 原生支援 `repaint` / `cover`，不必等 M2，可在 M0 之後任何時間插入。

**M2 退路**：audio.cpp 試做在 Windows + 4GB 跑不起來時，改用 Python 版（diffusers / stable-audio-tools）跑同一個 Stable Audio 3 Small，保留能力，放棄 audio.cpp。

**M5 範圍**：只做「輸出方向」（音訊轉 MIDI / 譜）。MIDI 驅動生成不在範圍內。

## 二之一、App 路線（2026-11-09 起優先）

Peanut 決定先把 Music Studio 做成獨立 app，**M2–M5 暫停**，等 app v1 驗收後直接做在 app 裡。

### 決定

| 項目 | 決定 |
|---|---|
| 形態 | 像 yovoice 一樣重寫：Tauri 2（Rust）+ React 桌面 app |
| 程式碼位置 | 新 repo [`PeanutGT/Nusic-Studio`](https://github.com/PeanutGT/Nusic-Studio)，本 repo 的 skill 保留 |
| 生成引擎 | 保留 Python ACE-Step（`ace_worker.py`）當子行程；引擎接口留給之後的 audio.cpp |
| Rust 範圍 | 所有非 GPU 邏輯：設定與參數目錄、風格／情緒／詞庫／規劃／caption、佇列、作品庫、響度後製、品檢、匯出。Python 只跑 ACE-Step |
| 安裝 | 安裝檔只有數十 MB；首次啟動精靈用 uv 建環境、下載 PyTorch／ACE-Step／模型（進度條、可續傳、檢查顯卡），也可指定已裝好的 ACE-Step |
| 平台 | v1 只保證 Windows 10/11 + NVIDIA 4GB 以上；介面繁中 |
| 發佈 | Windows CI 建置安裝檔放 GitHub Releases，內建 Tauri 自動更新；不買簽章憑證（首次安裝有 SmartScreen 警告） |
| skill | 凍結在 v3.7（只修 bug）；app v1 驗收後改版成呼叫 app 本機 API 的客戶端。v3.7 的輸出當 Rust 版的對照基準 |

### 里程碑

| 里程碑 | 內容 | 驗收 |
|---|---|---|
| **A0** 骨架 | 新 repo、Tauri + React + TS 骨架、Windows CI 建置；從 v3.7 匯出對照資料（規劃、caption、品檢數值） | CI 綠燈、MSI 上能開出空視窗 |
| **A1** 引擎橋接 | Rust 啟動／監控／重啟 Python worker，單首生成、取消、顯存顯示；最小介面 | 原本的驗收標準（3050 連跑 3 次、取消有效、不掉 CPU 解碼） |
| **A2** 核心搬家 | 設定與參數目錄、風格／情緒／詞庫、規劃與 caption、佇列、作品庫改寫成 Rust | 對照測試：同一份 spec 的規劃與 caption 和 v3.7 一致 |
| **A3** 後製與品檢 | 線性增益響度（上限 TP −0.5 dB）、品檢（爆音、咔噠、斷尾、靜音、音量、發悶）、匯出 wav／mp3／flac | 對照測試：同一段音訊的響度與品檢結果和 v3.7 誤差在容許範圍內 |
| **A4** 完整介面 | 建立頁（含進階、樂器晶片）、佇列、作品庫試聽、設定頁參數表，追平儀表板 | Peanut 在 3050 上走完一首從規劃到匯出 |
| **A5** 安裝與發佈 | 首次啟動精靈、安裝檔、GitHub Releases、自動更新 | 在 MSI 用新的 Windows 帳號從安裝檔裝到生成成功；能從舊版自動更新到新版 |

App v1 = A0–A5 全部 ✅。之後：skill 改成 app 客戶端（v4），再依序在 app 裡做 M2–M5。

推進規則照舊：一步一個分支一個 PR、最多一個里程碑停在 🛠。雲端沒有 Windows 與 GPU，A1 起的實測都走 MSI。

### 進度

- ⬜ A0 骨架
- ⬜ A1 引擎橋接
- ⬜ A2 核心搬家
- ⬜ A3 後製與品檢
- ⬜ A4 完整介面
- ⬜ A5 安裝與發佈

## 三、進度清單

### M0 穩定 v3
- ✅ 全新 clone 測試全過、CI 跑單元測試（v3.1.1，PR #2；2026-10-31）
- ✅ 疑難排解文件：伺服器與直接執行兩條路徑（v3.1.2，PR #4；2026-10-31）
- ✅ 4GB 實測：連跑 3 次不卡死（2026-10-31：93 s / 16 s / 17 s，第 2、3 次沿用同一個 worker，不重載模型；顯存峰值約 3.5 GB）
- ✅ 4GB 實測：取消有效（2026-10-31：擴散中與解碼中取消都停掉 worker，約 2 秒內顯存歸零）
- ✅ 4GB 實測：不掉到 CPU 解碼（2026-10-31：無 cpu_decode、無 OOM）
- 🛠 實測小問題：重複警告、取消後顯存數字過時、第一首「準備中」沒有說明（v3.2.0，下次實測時順便確認）
- ✅ Peanut 試聽過關，移除 WIP 標記（2026-10-31：「可以接受」；有些聲音像電子雜訊，戰敗的「戰爭與犧牲」感不夠 → 見下方「品質改善」）

### 品質改善（試聽回饋，不擋里程碑）
- 🛠 低階顯卡（int8、無 LM）的電子雜訊感：比較 int8 與非量化、步數、`offload` 對音色的影響（2026-11-01 同 seed 對照：關掉 int8 後 Peanut 聽起來破碎感變少；v3.4.1 low tier 預設改成不量化）
- 🛠 描述 → 情緒的貼合度（v3.4.0 加 `war-requiem` 風格與「犧牲、悲壯」詞庫；caption 在規劃時已顯示；v3.4.1 caption 改用具體音色，2026-11-01 RTX 3050 同 seed 試聽 Peanut：「還可以」）：戰敗規格退回 `nature-piano` 加合成墊與 drone，沒有戰爭感。新增戰爭／戰敗風格（管弦安魂曲：大提琴、低音弦樂、悶住的軍鼓、法國號），詞庫補「戰敗、戰爭、犧牲、悲壯」，並在規劃時顯示 caption 讓使用者看得懂
- 🚧 讓使用者看得到、改得到所有生成參數：參數目錄 `defaults/knobs.json`、設定頁完整參數表（值、來源層、範圍、說明、存到哪一層、還原）、建立頁「進階」單首調整、`msconfig.py knobs`、`plan --param`（v3.6.0）
- 🛠 高音發悶、像被擋住（2026-11-09 Peanut 試聽 war-requiem／rpg-town）：主因是 ffmpeg `loudnorm` 默默改成動態壓縮；v3.7.0 改成單一線性增益，品檢新增 `dull`。原始 turbo 8 步高頻本來就偏少，sft 50 步只對部分曲子有幫助且 4GB 上 60 秒以上會逾時；待重新生成後試聽
- ⬜ 低階顯卡上標出容易產生雜訊的 tag（合成墊、drone 等），規劃時提醒（可直接標在詞庫的樂器條目上）
- 🛠 樂器選擇：風格建議／避開樂器、使用者可指定或排除、儀表板樂器晶片（v3.4.0；2026-11-01 RTX 3050 已生成二胡＋古箏版、QC 無問題，待 Peanut 試聽：指定樂器有沒有真的出現）

### M1 自動品檢
- ✅ 響度預設：影片 −14、遊戲 −16、背景 −18 LUFS（v3.3.0；2026-10-31 GPU 驗收：遊戲預設約 −16 LUFS）
- ✅ 自動品質檢查：每次生成後檢查爆音、咔噠聲、斷尾、靜音、音量（v3.3.0、v3.3.1 修誤報；2026-11-01 Peanut 試聽：「大概 OK」）

### 重繪 / 翻唱
- ⬜ spec 加 `task` / `source`，接上 ACE-Step `repaint` / `cover`
- ⬜ 儀表板上傳來源音訊

### M2 第二引擎（暫停，app v1 後做在 app 裡）
- ⬜ 可行性試做：audio.cpp + Stable Audio 3 Small 在 Windows + 4GB
- ⬜ 音效生成（`kind: "sfx"`、音效風格庫、`sfx-pack` 流程）
- ⬜ remix

### M3 MCP
- ⬜ stdio MCP 伺服器（生成、佇列、作品庫）

### M4 人聲
- ⬜ spec 加 `lyrics` / `vocal_language`，送真歌詞給 ACE-Step
- ⬜ 歌詞撰寫參考與流程關卡

### M5 轉譜
- ⬜ 音訊轉 MIDI
- ⬜ MIDI 轉簡譜 / 樂譜

### 終點之後
- ⬜ 語音 / TTS
- ⬜ 換卡後重評：接回原模型（如 YuE2）
