# music-studio 更新紀錄

格式參考 [Keep a Changelog](https://keepachangelog.com/zh-TW/1.1.0/)，版本號遵循 [語意化版本](https://semver.org/lang/zh-TW/)。

## [3.4.1] - 2026-11-01

### 變更
- 4GB 以下（low tier）不再預設 int8 量化：同 seed 對照，int8 版有破碎音質，關掉後 Peanut 聽起來明顯變好；RTX 3050 4GB 一首 60 秒約 35-65 秒（int8 約 20 秒），沒有爆顯存、沒有掉 CPU 解碼。真的爆顯存時可用 `msconfig.py set hardware.tiers.low.quantization int8_weight_only` 改回

## [3.4.0] - 2026-11-01

### 新增
- 風格可以指定樂器：每個風格有建議樂器（`instruments.suggest`）與要避開的樂器（`instruments.avoid`），避開的樂器會從風格與情緒標籤中拿掉；建議的樂器 caption 裡沒有時會補上
- 自己指定樂器：`msconfig.py plan --instruments erhu,guzheng`（取代風格的建議）、`--avoid-instruments drums`；描述裡講到的樂器永遠優先，風格原本會避開時附提醒。`msconfig.py instruments [--style S]` 列出可用的樂器 id
- 儀表板「樂器」晶片：依風格預先標好 ✓／✕，點一下切換 使用 → 避免 → 不指定；「會送給 ACE-Step 的內容」多一列「樂器」
- 新風格 `war-requiem`（戰爭安魂曲）：大提琴、低音弦樂、悶住的軍鼓、法國號，避開合成器與 drone，給戰敗／戰爭／犧牲的場景
- 詞庫新增樂器：法國號、定音鼓、軍鼓、低音弦樂、雙簧管、單簧管、手風琴、曼陀林、琵琶、持續低音（drone）；新增「犧牲」「悲壯」
- `msconfig.py validate` 檢查風格裡的樂器 id 是否存在

### 變更
- 內建風格的 caption 改用樂理描述，不再堆模糊形容詞（warm、dreamy、epic 感受詞等）：寫明調式、和弦語彙與進行、節奏型、織體與音域、力度、樂器與演奏法，例如 lo-fi 改成「Dorian mode, minor seventh and ninth chords, swung boom bap drums」。感受交給情緒選項。測試會擋下內建風格裡的模糊詞（`msconfig.VAGUE_WORDS`），撰寫指南同步更新

## [3.3.1] - 2026-10-31

### 修正
- 自動品檢不再把結尾靜音誤報成「中間長靜音」：靜音後面到檔尾只剩極微弱的底噪時，視為結尾靜音（M1 GPU 驗收 3 次中有 2 次誤報 0:55–0:57）

## [3.3.0] - 2026-10-31

M1：自動品檢。

### 新增
- 每次生成完自動檢查每個版本：削波（爆音）、咔噠聲、結尾被切斷、中間長靜音、幾乎無聲、音量過小，附時間點。儀表板在版本比較台下方列出，有問題的版本標 ⚠；`library.py show` 的 `variants[].qc` 也看得到。門檻用 RTX 3050 上的真實作品校準過，鼓聲等正常的瞬態不會被當成咔噠聲
- 匯出時可選響度預設：影片平台 −14、遊戲 BGM −16、背景／讀書 −18 LUFS（真峰值 −1 dBTP），會蓋過用途裡的設定；`postprocess.py run --loudness`，自訂預設寫在 `postprocess.loudness_presets`
- 成品的品質報告也包含上述自動檢查（`report.issues`）

### 修正
- 成品的響度檢查改用實際套用的目標：用途設 −20 LUFS 的成品不再被誤報「偏離 −16」

## [3.2.0] - 2026-10-31

v3 通過 RTX 3050 Laptop 4 GB 實測與試聽，不再標示為 WIP：連跑 3 次（93 / 16 / 17 秒，第 2、3 次不重載模型）、擴散中與解碼中取消都有效、沒有 CPU 解碼。以下修正實測時發現的小問題。

### 修正
- 規劃時的警告（例如低階顯卡把版本數限制為 1）不再出現兩次
- 取消後儀表板不再顯示過時的「可用顯存」
- 第一首生成時，啟動 ACE-Step 工作程序的那段時間會顯示在「載入模型」階段並附說明，不再停在沒有說明的「準備中」；底部佇列也會顯示目前階段的說明

## [3.1.2] - 2026-10-31

### 變更
- `troubleshooting.md` 說明「透過伺服器」與「直接執行」兩種路徑的差別（模型常駐、取消、log 位置、CPU 解碼處理），並補上伺服器啟動失敗、`interrupted`、四分鐘無進度、取消後顯存沒釋放等狀況
- `quality.md` 說明伺服器在 CPU 解碼或 OOM 後會自動調整下一首的設定

## [3.1.1] - 2026-10-29

### 修正
- 從 GitHub 全新 clone 後有 2 項測試失敗：假 ACE-Step 的模型資料夾是空目錄，git 不會保存，現在改由測試自己建立
- CI 新增 music-studio 單元測試（Linux + ffmpeg + numpy）

## [3.1.0] - 2026-10-25

### 新增
- 儀表板改為深色錄音室機架風格；主畫面是版本比較台（所有版本疊在同一條小節時間軸上，共用播放頭，數字鍵切換）
- 底部佇列列出五個生成階段與經過時間，取消會真的停止顯卡上的工作
- `msclient.py`：Claude 與儀表板透過同一個伺服器排隊，模型常駐顯存，閒置 10 分鐘自動釋放
- `ace_worker.py`：常駐的 ACE-Step 工作程序，顯存保護與 CPU 解碼偵測；解碼退到 CPU 時警告，並自動收緊下一首的設定
- 詞庫補上遊戲常用詞（失敗、落寞、戰爭、遊戲等），並修正「畫面」等贅字造成的未匹配問題

### 變更
- 失敗或取消的工作不留下空的作品資料夾（會移到工作區的 `trash`）
- 低階顯卡（<8 GB）預設將擴散模型移出顯卡（`offload_dit_to_cpu`）
- 文字對比達 AA、手機版無橫向捲動、支援鍵盤操作與 `prefers-reduced-motion`

### 注意
- 常駐引擎已對照 ACE-Step 最新原始碼撰寫，尚未在各種顯卡上完整實測；舊的 `engine.py generate` 仍可作為後備。
